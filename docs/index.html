What our data shows

It isn't smarter. It just never grades its own work.

The rules aren't a promise the model makes. They're written in code, and the code checks every claim. These are claims about our system, measured on a public test suite of seven kinds of question.

CLAIM 1

No gaps filled from memory

Four models on the same code. No finished answer filled a gap with the model's own knowledge, by the suite's measures.

CLAIM 2

Every finding is checked

Every finding is copied from a page and checked against it. Commands must appear exactly as the page writes them.

OUR WORKING PROBLEM

Silent omissions

When something isn't found, the answer usually says so. But reading results by hand, we found answers that left a part out without a word, and our tests don't count those yet. That's our next focus, and you can help.

How it works

The AI proposes. The code decides what counts.

Each turn, the model sees the question, what it has found so far and the current page, and picks exactly one action. A visible Chromium window lets you watch every step.

SEARCH

Searches DuckDuckGo and shows the results with their real addresses.

NAVIGATE

Opens a page from the results or from the current page's links.

READ_MORE

Reads the next part of a long page, or jumps to the part whose heading names what's still missing.

DISCOVER

Records a finding, copied from the page. Code checks it is really there before it counts.

FINISH

Each part of the question is checked against the findings. The answer is then written only from what was found, and anything that wasn't is listed as not found.

A finding the page doesn't support is turned away, the model is told why, and it's sent back to the page.

Quick start

Runs on the computer you already have.

Built for a 7B model on an ordinary CPU, no graphics card needed. A run takes from about 10 minutes to an hour, so start it and let it work.

  1. Install LM Studio, download a model (developed with Qwen2.5-7B-Instruct), load it and start the local server (Developer tab → Start Server).
  2. Install the agent (Python 3.10 or later) and the browser it drives: 
    pip install localagentbrowser
python -m playwright install chromium
  3. Run it and type your question: 
    localagentbrowser
    When it finishes, read research_report.md: the answer, and every finding with the page it came from.

Good for

  • Facts, and lists with conditions
  • Comparisons with a recommendation
  • How-tos and explanations
  • Views from several sources
  • Looking things up in official documentation

Not yet

  • Anything behind a form, a login or a button. It reads pages; clicking is still to come.
  • Fast answers. A small model on a CPU takes its time.

Its searches, written from your question, go to DuckDuckGo, and it reads pages like any browser. The model and the report stay on your computer.

See two example reports, unedited, with what each got right and wrong.

The challenge

We can do better. If you think we're wrong, run it and show us.

The code, the test suite and every run are public. Pick a different model, write a harder question, find the answer it makes up, and tell us. And if you think we're right, help with the silent omissions. We named our own misses first.

# the seven-task suite: four hours or more on a CPU
python tools/regression.py --model qwen2.5-7b-instruct --minutes 90
