Autonomous web agent

LocalAgentBrowser

An AI that can't cover up. Give it a question: a model, local by default, searches the web, reads pages and copies what it finds, and code checks every copy against the page before it counts.

SEARCH→NAVIGATE→READ_MORE→DISCOVER→FINISH

L.A.B. for short, in a LAB COAT: Citations Over Assumed Truth. Our principle is Verification Over Trust.

New in 1.66: sturdier cloud runs, more of every answer checked in code, the console and browser side by side, and 85% on the standard 200 SimpleQA questions with Phi-4.

What our data shows

It isn't smarter. It just never grades its own work.

The rules aren't a promise the model makes. They're written in code, and the code checks every claim. These are claims about our system, measured on a public test suite of seven kinds of question.

CLAIM 1

No gaps filled from memory

Four local models on 1.64 and four cloud models on 1.66, each set on the same code. No finished answer filled a gap with the model's own knowledge, by the suite's measures.

CLAIM 2

Every finding is checked

Every finding is copied from a page and checked against it. Commands must appear exactly as the page writes them.

OUR WORKING PROBLEMS

Omissions and near-copies

Reading results by hand, we still find answers that leave a part out without a word, and findings that change one key word of the page ("foil" where the page says "épée") yet pass the word check. Our tests don't count either yet. That's our next focus, and you can help.

How it works

The AI proposes. The code decides what counts.

Each turn, the model sees the question, what it has found so far and the current page, and picks exactly one action. A visible Chromium window lets you watch every step.

SEARCH

Searches DuckDuckGo and shows the results with their real addresses.

NAVIGATE

Opens a page from the results or from the current page's links.

READ_MORE

Reads the next part of a long page, or jumps to the part whose heading names what's still missing.

DISCOVER

Records a finding, copied from the page. Code checks it is really there before it counts.

FINISH

Each part of the question is checked against the findings. The answer is then written only from what was found, and anything that wasn't is listed as not found.

A finding the page doesn't support is turned away, the model is told why, and it's sent back to the page.

Install

Runs on the computer you already have.

No graphics card needed. A run takes from about 10 minutes to an hour on a CPU, so start it and let it work. You'll need LM Studio (free), which runs the model on your computer, unless you use cloud models.

Windows: the installer

  1. Install LM Studio (not needed if you'll only use cloud models).
  2. Download LocalAgentBrowser-1.66-setup.exe from the latest release and run it. If Windows says it protected your PC, click More info → Run anyway: the installer isn't code-signed yet.
  3. Pick what to install and one of the four tested models; setup downloads it through LM Studio, and the browser the agent uses. Cloud models are optional and off unless you tick them. No administrator rights, no Python needed.
  4. In LM Studio, load the model with a context length of 8192 and start the local server (Developer tab → Start Server). With cloud models, set your key in the OPENROUTER_API_KEY environment variable instead.
  5. Open LocalAgentBrowser from the Start menu and type your question. The report opens in your browser when it's done.
Download for Windows

Any system: pip

Python 3.10 or later, in a virtual environment:

python -m venv venv
venv\Scripts\activate
pip install localagentbrowser
python -m playwright install chromium
localagentbrowser

On macOS or Linux, activate with source venv/bin/activate. Cloud models without the installer: the settings are in the README's FAQ. In LM Studio, load the model with a context length of 8192 and start the local server.

Good for

  • Facts, and lists with conditions
  • Comparisons with a recommendation
  • How-tos and explanations
  • Views from several sources
  • Looking things up in official documentation
  • Fast answers, with cloud models turned on

Not yet

  • Anything behind a form, a login or a button. It reads pages; clicking is still to come.
  • Fast answers on a CPU alone. A small local model takes its time; turn on cloud models for speed.

Local by default: searches go to DuckDuckGo and pages load like in any browser, while the model and the report stay on your computer. Cloud models are an option you turn on yourself, with your own key; then your prompts and the pages read go to the cloud provider.
